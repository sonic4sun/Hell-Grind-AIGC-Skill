# 竖屏连续剧层（Vertical Episodic Series Layer）

v2 schema 面向单部影片设计，没有"集数"概念。本层专门针对**竖屏微短剧"爽剧"**这一具体子类型：每集固定约 2 分钟（120 秒）、数十集连载、每集必须独立成钩、靠情绪节奏和付费点驱动追看，不是泛用的"多集内容"扩展。在 v2 之上叠加集数分组、开场/结尾钩子、单集节奏契约三层要求，不改动任何既有文件的表头，纯增量扩展。

## 新增文件：`01_story/episodes.csv`

```text
episode_id,episode_order,title,scene_ids,runtime_seconds_target,ending_hook_type,ending_hook_description,pay_gate,status,notes
```

- `episode_id`：`EP##`（两位数字，`EP01`–`EP99`）。
- `episode_order`：全剧集数序号，纯数字，用于排序。
- `scene_ids`：属于本集的 `scene_id` 列表，分号分隔（沿用 schema 既有的多值字段惯例，见 `references/project-schemas.md` 的"多值字段用分号"规则），例如 `SC001;SC002;SC003`。场次编号在全剧范围内连续递增、不按集重置——`SC###-SH###` 的镜头 ID 因此不需要任何改动就能唯一定位到具体某一集的具体镜头。
- `runtime_seconds_target`：本集目标时长（秒），**默认锚定 120（2分钟）**，允许 90–150 浮动，超出此区间视为需要重新拆集，不是正常创作弹性。
- `ending_hook_type` / `ending_hook_description`：见下方"结尾钩子词表"。
- `pay_gate`：`true/false`，标记这一集是否是付费解锁点。
- `status`：`planned/drafted/locked`。

场次到集数的归属只通过 `episodes.csv` 的 `scene_ids` 字段单向引用 `03_scenes/scenes.csv`，不反向修改 scenes 表。`episodes.csv` 不在 `validate_project.py` 的 `REQUIRED_TEXT_FILES` 清单里，校验器不会因为这个新文件而改变既有行为；后续如需强校验，在校验器里新增独立检查函数，不要动既有的 scenes/shots 检查逻辑。

## 结尾钩子词表

每一集最后一颗镜头（即该集 `scene_ids` 最后一个场次里 `shot_order` 最大的镜头）必须在对应 `04_shots/shots.csv` 行的 `notes` 字段标注钩子类型，取值：

| 类型 | 说明 | 对应处理 |
|---|---|---|
| `reversal` 反转 | 上一秒的认知在本镜被推翻 | L1 验收目标写清楚"被推翻的认知是什么"；该认知必须在前面镜头已被明确建立 |
| `crisis` 悬念/危机 | 角色处于未解决的生死或身份危机 | L7 `must_not_appear` 明确禁止"危机被提前化解的画面" |
| `new_character` 新角色登场 | 结尾引入此前未出现的资产 | L2 引用范围锁定"只露出足以引发好奇的最少特征"，完整资产表还不批准 |
| `confrontation_line` 冲突台词卡点 | 在一句强台词上硬切 | 对白/音频层的 `audio_cues` 标注"卡在台词最后一个字，不留尾静默" |
| `identity_reveal` 身份揭露 | 揭露某资产此前隐藏的状态 | `02_assets/asset-state-matrix.csv` 新增一行批准状态，`must_hold` 明确排除揭露前的旧状态残留 |

## 开场钩子词表

每一集第一颗镜头（`scene_ids` 首个场次里 `shot_order` 最小的镜头）必须在对应 `04_shots/shots.csv` 行的 `notes` 字段标注开场钩子类型，**3 秒内完成信息量交代，观众必须能在这颗镜头结束前判断人物关系与核心冲突**，取值：

| 类型 | 说明 | 对应处理 |
|---|---|---|
| `direct_conflict` 直接冲突型 | 当众打脸、背叛、对峙、激烈争吵，直接开演 | L1 验收目标不写背景说明，直接写"本镜发生的冲突事件" |
| `strong_suspense` 强悬念型 | 枪口对准主角、关键物证掉落、一通未知来电 | L7 `must_not_appear` 禁止提前露出悬念答案 |
| `extreme_contrast` 极致反差型 | 上一秒风光、下一秒坠落谷底，用并置制造张力 | 需要两个 `open_state`/`close_state` 在同一镜内完成反差，不能拆成两镜稀释 |

不允许"角色起床/通勤/环境介绍"式的说明性开场——这类镜头即使拍得再精致，也不满足竖屏爽剧第一秒留人的要求，应直接砍掉或后移成插叙。

## 单集情绪节奏契约

竖屏爽剧单集不是"一段连续叙事"，是一个完整的情绪闭环：**压抑（负面情绪累积）→ 假反转（看似要翻盘，实则更糟或另有隐情）→ 真打脸／爽感（情绪释放）→ 结尾钩子（把满足感立刻换成新的悬念）**。这个节奏用镜头序列在 `04_shots/shots.csv` 里体现，不新增字段，靠 `narrative_goal` 和 `notes` 两个既有字段承载：

- 每一集的镜头序列里，`narrative_goal` 应该能连成一条清楚的压抑→反转→释放弧线；写完一集的分镜后，把所有 `narrative_goal` 抽出来单独读一遍，读不出这条弧线就是节奏契约没满足，不是先跳去调整台词或运镜。
- 单一镜头的时长上限用 `init_project.py`／下游生成工具的秒数上限控制（`04_shots/shots.csv` 的 `duration_seconds`），竖屏短剧单镜通常不超过 15 秒，快节奏冲突场面可压到 3–5 秒。
- 前两集享有特殊的松紧要求：`episode_order` 为 1、2 的集数，压抑段落的镜头占比应明显高于后续集数——竖屏爽剧的观众留存模型要求主角在最初两集被四面八方打压到全剧最低点，后面才有得彈，这不是叙事偏好，是对应付费转化数据的结构要求。

## 竖屏（9:16）构图倾向

L5 摄影机层的公式结构不变（`camera_start`/`camera_path`/`camera_end`），但竖屏短剧的常用取值分布明显不同于横屏参考素材：

- 默认景别更紧：近景、特写、大特写的占比应显著高于中景、远景——横屏惯用的宽画幅环境镜头在竖屏里信息密度不足，容易读不清楚。
- 主运镜偏好"推"（push in / punch in）而非横向的摇（pan）——竖屏画面横向空间窄，横摇容易撞到画框边缘，纵深方向的推拉更稳定，也更贴近短剧观众熟悉的"重点时刻猛推特写"节奏。
- 多主体镜头（L3 空间层）在竖屏里应优先用"前后景分层"而非"左右分层"表达空间关系，理由同上。
- 建立项目时用 `init_project.py --resolution 1080x1920 --aspect-ratio 9:16` 一并设定交付规格，不要留着横屏默认值事后手改。

## 失败诊断的延伸

`failure-diagnosis.md` 的既有分类逐镜适用，不因集数结构而改变，新增一类专属集尾镜头：

**F-HOOK-WEAK**：集尾镜头没有兑现钩子承诺（例如标注 `reversal` 但画面没有推翻任何已建立的认知）→ 回到该镜的 L1 验收目标，检查"被推翻的认知"是否在前面镜头里已经被观众明确建立；没有就先补前置镜头再重写结尾，不要靠加强本镜的表演或运镜硬撑。

## 什么情况下读这份文件

- 项目是竖屏微短剧"爽剧"（每集约2分钟、数十集连载、靠钩子和付费点驱动追看），需要在既有 v2 schema 上追加集数分组时。
- 交付格式是竖屏（9:16）时，先读"竖屏构图倾向"一节再写 L5 层。
- 写一集的分镜前，先确认开场钩子（3秒内）和结尾钩子都已经选好类型，再动笔写单镜 prompt。
- 诊断"这集结尾不够抓人""这集开头留不住人""这集看起来很平"这类反馈时，先对照"单集情绪节奏契约"检查压抑→反转→释放弧线是否完整，再查 F-HOOK-WEAK，最后才考虑 `failure-diagnosis.md` 里其他层的分类。
- 本层只适用于"爽剧"这个具体子类型；如果是竖屏但节奏舒缓、不追求高频反转的系列内容（例如生活流Vlog式短剧），钩子表和节奏契约不强制套用，仅集数分组（`episodes.csv`）本身仍然适用。
